User prompt: як в компілятори записують булевий тип у 8 бітів? ir.IntType(8) це типу 1 якщо true і 0 якщо false?
Response: Так, саме так! У багатьох компіляторах та генераторах коду (зокрема в LLVM IR, де такий синтаксис як ir.IntType(8) або i8 є стандартом) булевий тип представляють як 8-бітне ціле число, де:
1 (або 0x01 у 16-рiчнiй системі) означає true
0 (або 0x00) означає false
Чому використовують 8 бітів (i8), якщо для булевого значення потрібен лише 1 біт?
Адресація пам'яті: Сучасні процесори не можуть адресувати окремі біти в оперативній пам'яті. Мінімальна адресовна одиниця пам'яті — це 1 байт (8 бітів). Щоб виділити змінну в пам'яті, зберегти її або зчитати за адресою, компілятору найпростіше виділити повноцінний байт.
Вирівнювання (Alignment): Робота з даними, розмір яких кратний байту, значно прискорює виконання програм на рівні заліза та процесорних регістрів.
Як це працює на вищих і нижчих рівнях abstraction:
В LLVM / IR: Ви можете побачити ir.IntType(1) (1 біт, i1) для суто логічних операцій (наприклад, у переходах br i1 %cond, label %true_block, label %false_block), але при виділенні пам'яті в стеку або купі (alloca, store, load) компілятори майже завжди приводять i1 до i8 (або IntType(8)), розширюючи значущий біт.
Перевірка значень у C/C++ та ABI: У мові C/C++ тип bool зазвичай має розмір sizeof(bool) == 1 (тобто 1 байт = 8 бітів). При цьому значення 0 вважається false, а будь-яке ненульове значення (не лише 1, а й 2, 255 тощо) під час логічного розгалуження сприймається як true. Проте під час присвоєння true компілятор гарантовано записує в ці 8 бітів саме 1.

THE LANGUAGE One statement per line; blank lines are allowed. • Three types: i32 and i64 are integers, bool is a boolean with the literals true and false. i64 a{10}, bool b{true}, i32 x{15}. • A variable is const unless marked mut: i64 mut y{x}. The initialiser in {} is mandatory. y := y * z + a assigns; only a mut variable may be assigned. • Arithmetic is a chain of constants and variables joined by +, -, *; * binds tighter, equal precedence groups from left to right. It works on integers only; the result has the wider of the two types. • == and != compare two integers or two bools and give a bool. One comparison per expression, and it binds weaker than arithmetic: x * 2 != y + 5 compares the two results. • An i32 value may go into an i64 variable. Nothing else converts: an i64 never goes into an i32, a bool never meets an integer. • exit y · exit 42 · exit true prints Program exit with result and ends the program. It takes a constant or a variable, never an operation; it is the last statement and there is exactly one. • A variable is declared once, before its first use. Names are letters, digits and _, not starting with a digit; i32, i64, bool, mut, exit, true, false are reserved. Constants are decimal numbers without a sign. Not in the language, and therefore a compilation error: parentheses; /, <, > or any operator other than + - * == !=; a single = or !; a sign in front of a constant or a name; two comparisons in one expression; two statements on one line; a declaration without {}; anything after exit. TASK 2 — THE SEMANTIC PASS (1.5 POINTS) A check that lives inside the code generator runs only when code is generated, and it fails halfway through building the IR. The classic ticket is “the compiler crashed” where the honest answer was “line 3: an i64 does not fit into an i32”. A pass of its own rejects the program before a single instruction exists, and can be tested without LLVM at all. A walk of its own A class of its own — SemanticChecker — with one visit_* per node kind, run on the whole tree before the code generator is constructed. It owns the symbol table now: name → declaration, and the declaration knows its type and whether it is mut. An expression visit returns the type it computed and stores it on the node (node.type); a name stores the declaration it resolved to (node.decl). That is the whole contract with Task 3: the generator reads those two fields and looks nothing up. The type rules • A decimal constant has the narrowest type it fits: 10 is i32, 3000000000 is i64, 99999999999999999999 is an error. • + - * take two integers; the result has the wider type (i32 + i64 is i64). A bool operand is an error. • == != take two integers (any mix) or two bools; the result is bool. A bool against an integer is an error. • An i32 value may initialise or be assigned to an i64 variable.
