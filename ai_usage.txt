A declaration goes into the top frame, and only the top frame is checked for a duplicate — so a name from an outer frame may be declared again inside, with any type (shadowing). A use walks the frames from the top down and takes the first hit; a name that is in no frame is “used before its declaration”, and that includes a name whose frame has already been popped.
Response: У цьому контексті фрейм (frame / кадр) — це окремий словник (таблиця) змінних для одного конкретного блоку коду (глобального рівня або блоку { ... }).
Замість одного загального словника змінних {"a": decl1, "b": decl2}, вся таблиця символів стає стеком (списком) таких словників: [ frame_global, frame_block1, frame_block2 ].
Як це працює на практиці
1. Створення та знищення фреймів (Push / Pop)
При вході в дужки {: У стек додається новий порожній словник (push). Це створює нову локальну область видимості.
При виході з дужок }: Найвищий словник зі стеку видаляється (pop). Усі змінні, оголошені всередині цього блоку, перестають існувати.
2. Оголошення змінної (Declaration)
Коли ви оголошуєте нову змінну, перевірка на повторне оголошення (дублікат) відбувається тільки у найвищому (найновішому) фреймі:
Якщо у найвищому фреймі вже є така змінна → помилка redeclared variable.
Якщо така змінна є у зовнішньому (нижчому) фреймі, але відсутня у найвищому → це дозволено! Локальна змінна створюється у найвищому фреймі та перекриває (shadows) зовнішню змінну.
3. Використання змінної (Lookup)
Коли змінна використовується в виразі або присвоєнні, пошук іде зверху донизу по стеку (від найновішого локального фрейму до найстарішого глобального):
Береться перший знайдений результат (тобто найближча локальна змінна).
Якщо пройшли весь стек до дна і нічого не знайшли (або якщо фрейм, де вона була, вже видалено через pop) → помилка undeclared variable.

class SymbolTable:
    def __init__(self):
        # Починаємо з одного глобального фрейму
        self.frames = [{}]

    def push_frame(self):
        """Викликається при вході в блок '{'"""
        self.frames.append({})

    def pop_frame(self):
        """Викликається при виході з блоку '}'"""
        self.frames.pop()

    def declare(self, name, node, err_line, err_col):
        """Оголошення змінної — перевіряємо ТІЛЬКИ верхній фрейм"""
        top_frame = self.frames[-1]
        if name in top_frame:
            raise_err(1, err_line, err_col, ue_part=name) # redeclared variable
        top_frame[name] = node

    def lookup(self, name, err_line, err_col):
        """Пошук змінної — ідемо ЗВЕРХУ ДОВИЗУ по стеку"""
        for frame in reversed(self.frames):
            if name in frame:
                return frame[name] # Знайшли найближчу область видимості
        
        raise_err(2, err_line, err_col, ue_part=name) # undeclared variable

Response: Фрейми відкриваються та видаляються у чекачі (семантичному аналізаторі / CheckerVisitor) точно під час обходу вузла Block у вашому AST.
Коротке правило
Глобальний фрейм: Відкривається один раз на самому початку всієї програми.
Локальний фрейм:
Відкривається (push_frame): коли чекач заходить у вузол Block (перед обробкою інструкцій всередині {).
Видаляється (pop_frame): коли чекач закінчує обробку цього Block (після перевірки останньої інструкції перед }).
Як це виглядає в коді чекача (CheckerVisitor)
Коли ви обходите AST, у вас є метод для обробки блоків. Усе управління фреймами відбувається саме в ньому:
class CheckerVisitor:
    def __init__(self):
        self.symbols = SymbolTable() # При створенні вже є 1 глобальний фрейм: [{}]

    def visit_program(self, node):
        # 1. Перевіряємо глобальні оголошення
        for stmt in node.statements:
            self.visit(stmt)
        
        # 2. Перевіряємо глобальний exit
        self.visit(node.exit_stmt)

    def visit_block(self, node):
        # -------------------------------------------------------------
        # Вхід у блок '{': створюємо новий локальний фрейм!
        # -------------------------------------------------------------
        self.symbols.push_frame()

        # Обходимо всі інструкції ВСЕРЕДИНІ цього блоку.
        # Усі нові decl будуть потрапляти у цей новий фрейм,
        # а пошук змінних буде спочатку дивитися сюди.
        for stmt in node.statements:
            self.visit(stmt)

        if node.exit_expr:
            self.visit(node.exit_expr)

        # -------------------------------------------------------------
        # Вихід з блоку '}': знищуємо локальний фрейм!
        # Усі змінні, оголошені в цьому блоці, "згорають".
        # -------------------------------------------------------------
        self.symbols.pop_frame()

2. Виділення пам'яті для змінних (Slots у entry блоці)
У LLVM IR усі інструкції alloca (виділення стекового місця під змінні) повинні знаходитися в першому базовому блоці функції (entry), незалежно від того, у якому глибинному блоці { ... } чи if оголошено змінну.
Чому це важливо:
Якщо створити alloca всередині гілки then, ця змінна буде недоступна у гілці else.
Оптимізатор LLVM (mem2reg) вміє перетворювати змінні зі стеку у швидкі регістри тільки якщо alloca знаходиться в entry блоці.
При затіненні змінних (shadowing) дві різні Decl просто створять дві окремі alloca в entry блоці — ніяких додаткових дій для підтримки затінення у кодогенераторі робити не потрібно.

3. Обробка exit усередині гілок if
Інструкція exit генерує виклик printf і LLVM-інструкцію ret (повернення з функції).
Інструкція ret робить базовий блок термінованим (is_terminated == True).
Завдяки перевірці if not self.builder.block.is_terminated: у розгалуженні, ваш генератор не буде додавати зайвий br merge_bb після ret. Це запобігає виникненню синтаксичної помилки "двох термінаторів в одному блоці".
Якщо і then, і else закінчилися через exit, блок merge_bb залишиться без вхідних переходів, але буде валідним порожнім блоком (або в нього потрапить глобальний exit програми).
